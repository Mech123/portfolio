Pre Processing

This page summarizes the full preprocessing pipeline used to prepare Germany electricity demand and weather features for short-term load forecasting (SARIMA, LSTM, Hybrid, Ensemble). The steps below are taken from the project preprocessing notebook.

Links

  • Dataset (OPSD Time Series, 2020-10-06): Open dataset source
  • Preprocessing notebook (GitHub): Open preprocessing.ipynb
  • Optional (recommended): add processed file into the website repo at electricity-demand-forecasting-site/assets/data/processed_data_60min.csv and link it here as: ../assets/data/processed_data_60min.csv

Pipeline (Interactive Step-by-step)

Click each step to expand. This is a static interactive view (no backend required), suitable for Netlify.

Configuration
  • Forecasting focus: Germany electricity demand (hourly)
  • Target series created as: target_load
  • Weather merged into the same hourly timestamps
Step 1: Data Loading and Initial Inspection
  • Loaded OPSD time-series data (electricity load and related energy signals).
  • Checked schema, timestamp format, duplicates, and basic statistics.
Step 1.5: Weather Data Integration
  • Merged population-weighted weather data with the electricity time index.
  • Key weather features include temperature, wind speed, cloud cover, humidity, precipitation and solar radiation.
  • Added degree-day features: heating_degree_days and cooling_degree_days.
Step 2: Missing Data Analysis
  • Computed missingness per feature and across time.
  • Identified gaps introduced by alignment and external data availability.
Step 3: Feature Selection
  • Selected Germany-relevant load columns and created a unified target column.
  • Kept weather and engineered features that help short-term forecasting.
Step 4: Timestamp Validation and Gap Filling
  • Reindexed timestamps to create a continuous hourly timeline.
  • Validated ordering and ensured consistent time-frequency.
Step 5–6: Outlier Detection and Treatment
  • Detected outliers using IQR and Z-score.
  • Treated outliers by clipping to robust bounds (stabilizes training).
Step 7: Missing Value Imputation
  • Filled missing values using forward/back fill and interpolation.
  • Used safe fallback strategies to avoid leaving gaps for model training.
  • Special handling for load series continuity where needed.
Step 8: Calendar Feature Engineering
  • Added time features (hour, day-of-week, month, etc.).
  • Added cyclic encodings for periodic signals (sin/cos).
  • Created time-of-day and season indicators.
Step 9: Lagged and Rolling Feature Engineering
  • Created lag features for target load (e.g., 1h, 24h, 168h lags).
  • Added rolling mean/std windows and EMA features.
  • Added “same hour last week” features to capture weekly seasonality.
Step 10: Weather Proxy Features
  • Created proxy features for solar/wind/temperature-driven signals.
  • Helps models capture weather-demand interactions in a compact form.
Step 11–13: Encoding, Infinite Value Handling, Normalization
  • Encoded categorical features (time-of-day, season, etc.).
  • Handled infinite values safely.
  • Normalized features to improve training stability (especially for LSTM).
Step 14–15: Final Dataset Creation and Export
  • Created the final processed dataset for modeling.
  • Exported the processed CSV and produced summary information for reporting.
Step 16: Class Imbalance Handling (Cost-Sensitive Learning)
  • Introduced cost-sensitive learning for imbalanced conditions (e.g., peak vs non-peak situations).
  • This avoids resampling methods that can break temporal dependencies in time series.
